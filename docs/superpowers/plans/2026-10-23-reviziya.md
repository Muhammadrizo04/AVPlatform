# Reviziya (2-bosqich) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Revizor telefonda (brauzer) filial/bo'lim AV'larini skanerlab yoki qidirib belgilaydi; hisobchi solishtirish vedomostini ko'radi, farqlarni taqsimotga qo'llaydi va dalolatnoma PDF chiqaradi.

**Architecture:** Yangi Django ilovasi `reviziya`: modellar (Reviziya, ReviziyaKutilgan surati, ReviziyaQayd, ReviziyaQollash), servis (ochish/qayd/yakunlash/qo'llash), sof `solishtir` funksiyasi, panel sahifalari (CoreUI qobig'i) va revizor uchun alohida yengil mobil shablon (HTMX). Taqsimot o'zgarishlari faqat mavjud `vositalar.amallar` orqali.

**Tech Stack:** Django 5.2, PostgreSQL, HTMX, CoreUI 5 (panel), WeasyPrint (PDF), openpyxl (`hisobotlar.excel.jadval_xlsx`), brauzer `BarcodeDetector` API (kutubxonasiz).

**Spec:** `docs/superpowers/specs/2026-10-23-av-platforma-2-bosqich-reviziya-design.md`

## Global Constraints

- Interfeys matni — o'zbek (lotin); kod identifikatorlari — o'zbekcha nomlar (loyiha uslubi).
- 1C'ga hech narsa yozilmaydi; filial platformada o'zgarmaydi; taqsimot soni faqat 1C'dan oshadi (ortiqcha — faqat qayd).
- Rol va filial cheklovi queryset darajasida (`hisoblar.huquqlar.filial_bilan_chekla`) — sahifa, HTMX bo'lak, Excel, PDF, rasm URL'larida.
- Pul summasi faqat `pul_korish` huquqi bilan (sahifa, Excel, PDF).
- Tashqi CDN/shrift/JS kutubxona yo'q (ichki tarmoq).
- Reviziya raqami advisory lock kaliti `7310003`; ko'rinishi `RV-%06d`.
- Testlar: `venv\Scripts\python.exe -m pytest -q` (PostgreSQL). Python 3.12 bilan mos kod.
- Holatlar: `ochiq`, `yakunlangan`, `qollangan`, `bekor`.
- Mobil tegish nishonlari ≥ 44px; panel tokenlari (DESIGN.md) ishlatiladi.

## Review Focus

1. **Snapshotdan keyin taqsimot o'zgargan** (МОЛ akti, 1C sinxron kamaytirdi) va qo'llash bosildi — o'sha qator «Taqsimot o'zgargan» xatosi bilan o'tkaziladi, qolganlari qo'llanadi, 500 yo'q (Task 4 testi).

### Task 3: Solishtirish (vedomost hisobi)

**Files:**
- Create: `reviziya/solishtir.py`, `reviziya/tests/test_solishtir.py`

**Interfaces:**
- Consumes: Task 1 modellari.
- Produces:
  - `@dataclass(frozen=True) class VedomostQator: guruh: str; av_id: int | None; av_nomi: str; inv: str; bolim_id: int | None; bolim_nomi: str; holat: str; kutilgan: Decimal; topilgan: Decimal; farq: Decimal; nishon_bolim_id: int | None = None; nishon_holat: str = ""; qr_matn: str = ""; kalit: str`.
  - Guruh qiymatlari: `"topildi"`, `"holat_boshqa"`, `"boshqa_joyda"`, `"kam"`, `"topilmadi"`, `"ortiqcha"`.
  - `kalit` — barqaror satr (`f"{guruh}:{av_id}:{bolim_id}:{holat}:{nishon_bolim_id}:{nishon_holat}"`, noma'lum QR uchun `f"ortiqcha:qr:{qr_matn}:{bolim_id}"`) — qo'llashda ishlatiladi.
  - `solishtir(reviziya) -> list[VedomostQator]` va `jamlar(qatorlar) -> dict[str, Decimal]` (guruh → jami soni).

Algoritm (signatura va testlar to'liq aniqlamaydi):
1. Har AV uchun `(bolim, holat) → kutilgan` va `→ topilgan` yig'indilari.
2. Har (av, bolim): kutilgan va topilgan **jami** teng bo'lsa — holatlar bo'yicha teng qismi `topildi`, holatlar farqi `holat_boshqa` (kutilgan holatdan topilgan holatga, `min` miqdor bilan).
3. Har AV bo'yicha bo'limlar kamomadi (`kutilgan_jami - topilgan_jami > 0`) va ortiqchasi; kamomad bo'limlari pk tartibida ortiqcha bo'limlari bilan `min(kam, ortiqcha)` juftlashadi → `boshqa_joyda` (`bolim_id`=manba, `nishon_bolim_id`=topilgan joy, `holat`=manba qatorining holati).
4. Qolgan kamomad → `topilmadi` (shu bo'limda topilgan 0) yoki `kam`; qolgan ortiqcha → `ortiqcha`. AV'siz qaydlar → `ortiqcha` (`qr_matn` bilan).

  - `test_boshqa_joyda_juftlik`: A xonada kutilgan 2, B xonada topilgan 2 → `boshqa_joyda` 2 (`bolim_id=A`, `nishon_bolim_id=B`), `topilmadi` yo'q.
